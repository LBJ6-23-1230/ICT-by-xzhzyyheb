# 知学 Mate 华为 ICT 大赛 AgentArts 改造方案

日期：2026-10-23
阶段：方案基线（尚未创建或部署 AgentArts 云资源）

## 1. 改造目标

将“知学 Mate”从以 C4-AI 鸿蒙赛道为验收中心的应用，改造成以华为云 AgentArts
为智能体控制面、面向真实学习规划场景的多智能体应用：

> 学生只需表达目标、期限和可用时间，知学 Mate 即可调度诊断、规划、练习与评估
> Agent，结合课程资料和学习证据生成可执行计划，并在结果或约束变化时持续调整。

赛事定位采用截图中的“生活服务型 / 学习辅助”场景，同时突出“多 Agent 协同、
自主决策、MCP 工具调用、知识接入、效果评估”四类创新探索点。

## 2. 赛事要求基线

用户提供的赛题截图被视为本轮直接需求来源。截图中的硬性要求与本项目交付物映射如下：

| 赛题要求 | 本项目必须提供的证据 |
|---|---|
| 基于 AgentArts 完成智能体构建、编排与部署 | AgentArts 项目、智能体/工作流资产、已发布运行时、可重复调用记录 |
| 通过可视化 Demo 展示核心功能和交互 | HarmonyOS App 或 Web Demo，能真实调用 AgentArts 运行时，不使用录死结果 |
| 体现智能体设计、工具编排、知识接入、多 Agent 协作、效果评估 | 架构图、控制器与子 Agent、工作流画布、MCP 工具、知识库、Trace、评测报告 |
| 形成“场景识别→架构设计→技能编排→调试优化→部署上线”闭环 | 版本化开发记录、调试样例、失败修复、评测前后对比、部署及操作手册 |
| 入围后发布作品分享帖 | 社区文章草稿、Demo 截图/视频、使用指引、MCP/Skill 和知识库说明 |

华为云官方当前将 AgentArts定位为覆盖开发、运行、运营运维全生命周期的平台，支持
单智能体、工作流、多智能体、知识库、MCP、全链路 Trace 和自动评估。改造验收不能
只证明“调用了一个大模型 API”，而要证明上述平台资产确实参与了主业务链路。

## 3. 当前项目评估

### 3.1 可直接复用

| 资产 | 现状 | 新用途 |
|---|---|---|
| HarmonyOS/ArkTS App | 已有聊天、计划、练习、错题、知识库、轨迹等页面 | 作为可视化 Demo 和移动端交互入口 |
| 五角色 Agent | secretary、diagnosis、planner、exercise、assessment | 映射为 AgentArts 控制器与四个业务子 Agent |
| 确定性工具 | 优先级、排程、选题、判分、掌握度、重排、计划差异 | 封装成 MCP 工具，避免模型直接修改关键状态 |
| 业务数据与接口 | 用户、课程、DDL、资料、练习、计划、轨迹 | 继续作为业务真源，由网关和 MCP 层访问 |
| 工程质量资产 | OpenAPI 契约、幂等、账号隔离、数百项测试 | 作为 MCP 与 AgentArts 接入后的回归基线 |
| 演示数据 | 课程、DDL、错题和搭子样例 | 清洗后用于演示及 AgentArts 评测数据集 |

### 3.2 必须迁移或新建

| 缺口 | 当前状态 | 目标状态 |
|---|---|---|
| 智能体控制面 | Python 内自研顺序/规则编排 | AgentArts 多智能体控制器负责路由、等待、结束与子 Agent 调度 |
| 技能编排 | Python `ToolRegistry` 只在本进程调用 | 关键能力以自定义 MCP/插件发布并在 AgentArts 中真实调用 |
| 知识接入 | 本地解析、JSON/向量检索 | 课程资料进入 AgentArts 知识库，回答保留来源引用 |
| 模型与提示词 | DashScope/Qwen 配置写在本地服务 | AgentArts 中配置模型、系统提示词、变量和输出结构 |
| 效果评估 | 以单元/接口测试为主 | 新增 AgentArts 评测集、评估器、基线与优化后对照 |
| 云端部署 | 本机 Flask + 局域网 App | AgentArts 已发布运行时；Demo 经服务端网关安全调用 |
| 可观测性 | 自研 trace | AgentArts Trace 为主证据，业务 trace 作为补充并通过 `goalId` 关联 |
| 比赛材料 | 大量 C4-AI 规程、HAP、旧答辩材料 | 新建 ICT 赛题说明、AgentArts 资产清单、演示视频和社区分享材料 |

### 3.3 不再作为当前赛事验收中心

- C4-AI 的作品说明模板、页数、HAP 命名、旧演示时长和评分表。
- “集成若干鸿蒙特性”作为首要技术目标。
- 仅凭本地多 Agent 代码、HAP 或单元测试证明满足新赛题。
- 历史文档中的旧目录、旧比赛名称、旧测试数字和已过期模型说明。

HarmonyOS App、卡片、意图与跨端能力仍可保留为 Demo 的体验亮点，但其优先级必须低于
AgentArts 主链路、知识库、MCP、Trace、评测和部署。

## 4. 推荐目标架构

```text
HarmonyOS App / 可选 Web Demo
            |
            | HTTPS（仅传业务令牌，不携带华为云 AK/SK）
            v
知学 API Gateway（现 Flask 后端演进）
  - 身份映射 / 会话映射 / 输入输出适配 / 限流 / 审计
            |
            | AgentArts Runtime API
            v
AgentArts 多 Agent：知学秘书（控制器）
  |-- 学情诊断 Agent ---- AgentArts 知识库 / 学习证据工具
  |-- 学习规划 Agent ---- 课程、DDL、排程、计划提交 MCP
  |-- 练习辅导 Agent ---- 知识检索、题目生成、引用校验 MCP
  `-- 学习评估 Agent ---- 判分、掌握度、是否重排 MCP
            |
            v
AgentArts Trace / 自动评估 / 版本发布
            |
            v
现有 Repository（先 SQLite，后续可换云数据库）
```

### 4.1 为什么采用“低代码多 Agent + 自定义 MCP”

1. 多 Agent 控制器和工作流画布能直接形成赛事要求中的平台编排证据。
2. MCP 能复用当前经过测试的确定性业务逻辑，不让模型直接承担判分、数据写入和时间约束。
3. AgentArts 知识库、Trace 和评测可以覆盖当前项目最薄弱的“平台价值证明”。
4. 现有 App 和 API 无需一次性推倒，迁移可按场景逐步切换并保留回滚路径。

不推荐仅将当前 Flask 代码作为高代码 Agent 容器直接托管：这样虽然使用了运行时，
但难以充分展示可视化编排、知识接入、多 Agent 协作和平台评测。也不推荐把所有规则
重写为模型提示词，这会降低判分、状态写入和计划约束的可靠性。

## 5. AgentArts 资产设计

### 5.1 多 Agent 角色

| AgentArts 资产 | 主要输入 | 主要输出 | 可调用能力 |
|---|---|---|---|
| 知学秘书（控制器） | 用户目标、期限、可用时间、会话上下文 | 路由、汇总、澄清问题、结束条件 | 读取用户上下文、创建目标、查询任务状态 |
| 学情诊断 Agent | 学习证据、错题、资料知识点 | 有证据的薄弱点、置信度、待补测项 | 知识检索、证据查询、创建短测 |
| 学习规划 Agent | 诊断结果、课程表、DDL、可用时间 | 有取舍的计划和计划差异 | 优先级、时间预算、计划提交 |
| 练习辅导 Agent | 目标知识点、资料引用、难度、题量 | 有来源的练习和解释 | 知识检索、选题/生成、引用校验 |
| 学习评估 Agent | 题目、答案、旧画像 | 确定性得分、逐点更新、重排建议 | 判分、掌握度更新、重排判断 |

### 5.2 首批 MCP 工具

工具以“小而稳定、入参出参结构化、写操作可幂等”为原则。第一批建议：

1. `get_learning_context`：读取课程、DDL、空闲时间和当前目标。
2. `search_learning_materials`：按用户和资料版本检索片段并返回来源。
3. `get_learning_evidence`：读取错题、评估和掌握度证据。
4. `fit_plan_to_budget`：按可用分钟、DDL 和优先级裁剪计划。
5. `save_learning_plan`：以版本号和幂等键提交计划。
6. `create_grounded_exercise`：根据资料片段生成或选择练习。
7. `grade_exercise`：确定性判分，标准答案不进入公共上下文。
8. `update_mastery`：逐知识点更新画像。
9. `request_replan`：生成重排请求，不在评估步骤内隐式改计划。
10. `get_plan_diff`：输出新旧计划的可解释差异。

这些工具应复用 `app/tools/`、`app/services/` 和 Repository，而不是复制一套业务逻辑。

### 5.3 首批工作流

1. **目标建立与澄清**：识别目标 → 读取上下文 → 缺少期限/时间则等待输入 → 创建目标。
2. **证据不足闭环**：诊断证据不足 → 生成短测 → 用户作答 → 评估 → 再诊断。
3. **约束变化重排**：读取旧计划 → 时间/DDL 改变 → 排程 → 展示差异 → 提交新版本。

三条流程必须覆盖正常、等待用户、工具失败和安全停止四类路径。

## 6. Demo 主场景

主场景使用一个连续目标，而不是分散展示页面：

1. 用户说：“明天交数据结构作业，今晚只有 60 分钟，我刚上传了二叉树讲义。”
2. 知学秘书读取课程、DDL 和资料，诊断 Agent 发现遍历知识证据不足。
3. 练习 Agent 从知识库检索讲义片段并生成短测，界面展示来源。
4. 评估 Agent 调用确定性判分工具，逐知识点更新画像。
5. 规划 Agent 生成 60 分钟计划；用户改为 30 分钟后，系统展示保留、压缩和延期项。
6. App 展示 AgentArts 返回的角色、工具、依据、等待原因与计划差异。
7. 后台展示同一次 `goalId/sessionId` 对应的 AgentArts Trace 和评测结果。

对照场景至少包括：资料缺失、时间不足、工具超时、重复提交、越权访问五类，证明系统
不是固定脚本。

## 7. 分阶段实施

### P0：赛事切换与基线冻结

- 当前说明、目录和包元数据去 C4 化；历史材料标记为归档参考。
- 固化现有测试、接口、演示数据和功能清单，避免迁移时丢能力。
- 建立 AgentArts 资源命名、区域、账号、预算和密钥管理约定。

### P1：AgentArts 最小闭环 PoC

- 在 AgentArts 创建控制器、一个规划子 Agent 和最小工作流。
- 先用两个无副作用工具跑通“读上下文→给计划→返回 Demo”。
- 发布运行时，保存版本号、调用路径、Trace 和截图。

### P2：MCP 化现有工具

- 增加独立 MCP 适配层、鉴权、用户上下文、超时、审计和幂等。
- 先迁移读工具和排程，再迁移判分、画像与计划写入。
- MCP 工具加入契约测试、账号隔离测试和错误注入测试。

### P3：完整多 Agent、知识库与工作流

- 建立五角色、多 Agent 路由、三条工作流和停止边界。
- 课程资料接入 AgentArts 知识库，回答可回溯到资料片段。
- 删除主链路中与 AgentArts 重复的本地模型路由，保留显式降级。

### P4：Demo 与云端联调

- Flask 服务演进为 AgentArts 服务端网关；华为云凭据不得下发 App。
- App 聊天、工作流和 Trace 页面改读新的会话/事件模型。
- 增加流式反馈、等待输入、工具失败、重试和计划差异展示。

### P5：评测与优化

- 建立场景识别、工具选择、知识有据性、计划可执行性、安全性评测集。
- 在 AgentArts 中运行基线，按失败样本优化提示词、工具描述和工作流。
- 输出版本前后指标、失败案例、成本与延迟，不只展示成功截图。

### P6：提交与分享材料

- 形成技术方案、架构图、Agent/工作流/MCP/知识库资产清单、测试报告。
- 录制 Demo 和 AgentArts 控制台证据；准备部署与使用手册。
- 按截图要求准备开发者社区分享帖，包含方案、编排、知识库、MCP/Skill、操作说明和视频。

## 8. 验收门槛

项目只有同时满足以下条件，才可标记“AgentArts 改造完成”：

- AgentArts 上存在已发布、可调用的控制器/智能体/工作流运行时。
- Demo 的主场景真实调用该运行时，断开 AgentArts 后能被检测为失败或明确降级。
- 至少四个子 Agent 在真实 Trace 中有职责明确的路由和交接证据。
- 至少六个 MCP 工具被 AgentArts 调用，其中包含读、计算和受控写三类。
- 知识库结果带来源，跨用户资料无法互相检索。
- 至少三条主工作流及异常/等待分支通过端到端验收。
- AgentArts 评测集有基线、优化后结果和失败样本分析。
- 凭据不进入 App、仓库、日志、截图或提交包。
- 当前提交材料不再引用 C4-AI 模板、评分规则或旧赛事完成状态。

## 9. 主要风险与控制

| 风险 | 控制措施 |
|---|---|
| 只有平台截图，主链路仍走本地后端 | 增加运行时调用审计和断链测试；Demo 标记实际 `runtime/traceId` |
| AgentArts 与本地编排双写状态 | 每类写操作只保留一个提交入口；使用版本号和幂等键 |
| MCP 暴露越权工具或跨用户数据 | 服务端身份映射、工具白名单、参数校验、账号隔离测试 |
| 知识库展示有引用但内容无依据 | 评测检索命中率、有据性与引用一致性；人工抽样 |
| 云服务凭据被打进 HAP | 所有 AgentArts 鉴权只在服务端网关；提交前做密钥扫描 |
| 为展示多 Agent 而强制每次调用五个角色 | 控制器按意图路由；简单查询直达，复杂目标才进入协作闭环 |
| 旧材料造成赛事口径混乱 | 现役文档集中到本目录；旧目录后续统一归档并从交付清单排除 |

## 10. 启动实施前需要确认的外部条件

以下信息不影响本方案和本地代码准备，但会阻塞真实云端闭环：

- 可用且已实名认证的华为云账号，以及赛事 Token Plan/代金券状态。
- AgentArts 可用区域、团队成员权限和服务授权。
- 最终允许提交的 Demo 形态（HarmonyOS App、Web 或两者）。
- 作品/团队最终名称以及开发者社区发布账号。
