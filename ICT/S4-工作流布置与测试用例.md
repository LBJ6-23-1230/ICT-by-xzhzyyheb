# S4 工作流布置与测试用例

> 参照 `wf-diagnosis` 已跑通的布局整理。四条工作流统一用「开始 → 工具 → 判断 → 大模型 → 结束」的骨架，
> 判断节点只判 `isError`，业务分支交给大模型的输出字段。

## 通用约定

| 项 | 说明 |
|---|---|
| 身份参数 | 所有工具节点都必须接 `sessionRef ← 开始/sessionRef` |
| 工具输出 | 统一是 `content`（数组）+ `isError`（布尔）；正文在 `content[0].text`（一段 JSON 文本） |
| 结构化入参 | 工具的对象/数组参数都可传 JSON 文本（`contextText` / `planText` / `answersText` / `updatesText` / `assessmentText`） |
| 错误分支 | `isError = true` 时**不要**引用大模型输出（此时还没有），结束节点直接用固定文案 |
| 流式输出 | 大模型节点保持开启；结束节点 `result` 引用 `raw_output` |

统一的错误分支输出（复制到结束节点）：

```json
{"ok": false, "errorCode": "TOOL_UNAVAILABLE", "message": "工具调用失败：缺少身份引用或服务不可达"}
```

## 1. wf-diagnosis（已跑通）

```text
开始(query, sessionRef)
  └─► 工具 get_learning_evidence
        sessionRef ← 开始/sessionRef
        knowledgePointId ← 未配置（可选）
        │
        ├─► 判断  IF  isError 等于 true  ──► 结束（固定错误文案）
        │
        └─► ELSE ─► 大模型
                     query       ← 开始/query
                     tool_output ← 工具/content[0].text
                     │
                     └─► 结束  result ← 大模型/raw_output
```

**节点表**

| 节点 | 类型 | 关键配置 |
|---|---|---|
| 开始 | 系统 | `query`(string)、`sessionRef`(string) |
| 工具 | MCP | `zhixue-learning-tools / get_learning_evidence`；`sessionRef ← 开始/sessionRef` |
| 判断 | 逻辑 | `IF 工具/isError 等于 true`（优先级 1）；ELSE 走大模型 |
| 大模型 | LLM | `query ← 开始/query`；`tool_output ← 工具/content[0].text` |
| 结束 | 系统 | `result ← 大模型/raw_output`（错误分支用手写 JSON） |

**系统提示词**

```text
你是学情诊断专家。你会收到工具返回的 JSON 文本，先看 data.hasEvidence 字段。

规则：
- hasEvidence 为 false：只输出 {"needsShortTest": true, "message": "证据不足，建议先做 3 题短测"}，不要列薄弱点。
- hasEvidence 为 true：按证据列出最多 3 个薄弱点，输出
  {"needsShortTest": false, "weakPoints": [{"knowledgePointId": "...", "masteryScore": 42, "reason": "..."}], "evidenceIds": [...]}。
- 只能使用 JSON 里的数据，禁止补充外部知识；每个薄弱点必须带 reason 和 evidenceIds。
- 按薄弱程度排序，最多 3 个。
```

**测试用例**

| # | 输入 | 期望 |
|---|---|---|
| D1 | query=「帮我看看我哪里薄弱」，sessionRef=sref-demo-…0001 | `isError=false`；输出含 `needsShortTest`、`weakPoints`；`knowledgePointId=binary-tree-traversal` |
| D2 | 同上，但 `knowledgePointId=graph-algorithm` | 只返回该知识点的证据（或空列表） |
| D3 | query=「你好」 | 仍走工具；输出 `needsShortTest=false`，`weakPoints` 可为空数组 |
| D4 | sessionRef 改成 `sref-forged` | `isError=true`，走错误分支，输出 `TOOL_UNAVAILABLE` |
| D5 | sessionRef 留空 | 同 D4（工具返回 UNAUTHORIZED） |

## 2. wf-planner

```text
开始(query, sessionRef, availableMinutes)
  └─► 工具 get_learning_context
        sessionRef ← 开始/sessionRef
        │
        ├─► 判断 isError=true ──► 结束（错误文案）
        └─► ELSE ─► 大模型A（生成候选计划 JSON）
                      query           ← 开始/query
                      context         ← 工具/content[0].text
                      availableMinutes← 开始/availableMinutes
                      │
                      └─► 工具 fit_plan_to_budget
                            sessionRef       ← 开始/sessionRef
                            planText         ← 大模型A/raw_output
                            availableMinutes ← 开始/availableMinutes
                            │
                            ├─► 判断 isError=true ──► 结束（错误文案）
                            └─► ELSE ─► 大模型B（润色 + 解释取舍）
                                          plan  ← 工具/content[0].text
                                          query ← 开始/query
                                          │
                                          └─► 结束 result ← 大模型B/raw_output
```

**大模型A 提示词**

```text
你是学习规划专家。根据上下文生成一份候选计划（只输出 JSON，不要解释）。

规则：
- 任务来自 data.weakPoints 与 data.plan；每个任务包含 taskId、knowledgePointId、durationMinutes、status="pending"。
- 总时长不要超过 availableMinutes；超出的任务不要放进 tasks。
- 输出格式：{"planId":"plan-" + 会话标识, "version": <当前版本>, "tasks":[...]}。
```

**大模型B 提示词**

```text
你会收到 fit_plan_to_budget 的结果 JSON（含 plan.tasks 与 plan.unscheduledTasks）。
用中文向用户说明：保留了什么、压缩了什么、什么被延期以及原因。
要求：先给结论（总共多少分钟、几个任务），再列任务；不超过 200 字；不要编造未出现的任务。
```

**测试用例**

| # | 输入 | 期望 |
|---|---|---|
| P1 | query=「今晚只有60分钟怎么安排」，availableMinutes=60 | 计划总时长 ≤60；无延期或延期理由明确 |
| P2 | availableMinutes=30，上下文有两个 30 分钟任务 | 只排 1 个，另一个进 `unscheduledTasks` 且带 `deferredReason` |
| P3 | availableMinutes=0 | 全部延期，`scheduledMinutes=0` |
| P4 | 缺 sessionRef | `isError=true`，错误分支 |
| P5 | availableMinutes 传字符串「60」 | 与 P1 结果一致（服务端会转数字） |

## 3. wf-exercise

```text
开始(query, sessionRef, knowledgePointId)
  └─► 工具 search_learning_materials
        sessionRef ← 开始/sessionRef
        query      ← 开始/query（或知识点名）
        │
        ├─► 判断 isError=true ──► 结束（错误文案）
        └─► ELSE ─► 工具 create_grounded_exercise
                      sessionRef        ← 开始/sessionRef
                      knowledgePointId  ← 开始/knowledgePointId
                      count             ← 3
                      │
                      ├─► 判断 isError=true ──► 结束（{"needsMaterials": true, ...}）
                      └─► ELSE ─► 大模型（整理题面 + 标注来源）
                                    exercises ← 工具/content[0].text
                                    │
                                    └─► 结束 result ← 大模型/raw_output
```

**大模型提示词**

```text
你会收到 create_grounded_exercise 的结果 JSON。请整理成给用户看的题目列表。

规则：
- 每道题给出题干、四个选项（保留原顺序）、难度；**不要给出答案**。
- 在题目下方标注来源：文件名 + 章节（来自 sources.fileName / sources.headingPath）。
- 资料不足时（needsMaterials 或 errorCode=INSUFFICIENT_MATERIALS），只输出一句"当前资料不足以出题，请先上传相关讲义"，不要编题。
```

**测试用例**

| # | 输入 | 期望 |
|---|---|---|
| E1 | knowledgePointId=binary-tree-traversal，count=3 | 返回 3 道题，带 `sources[].fileName` |
| E2 | 上传过讲义后再测 | `sources` 里出现真实文件名与章节路径 |
| E3 | knowledgePointId 是不存在的点 | `isError=true`，输出 `needsMaterials` 或 `INSUFFICIENT_MATERIALS` |
| E4 | count=9（超上限） | 服务端夹到 5 道 |
| E5 | 未上传任何资料的用户 | 明确提示补资料，**不出现通用题库题** |

## 4. wf-assessment

```text
开始(query, sessionRef, answers)
  └─► 工具 grade_exercise
        sessionRef  ← 开始/sessionRef
        answersText ← 开始/answers        （JSON 文本）
        │
        ├─► 判断 isError=true ──► 结束（错误文案）
        └─► ELSE ─► 大模型A（解读得分与错因）
                      result ← 工具/content[0].text
                      │
                      └─► 工具 update_mastery
                            sessionRef  ← 开始/sessionRef
                            updatesText ← 大模型A/raw_output
                            │
                            └─► 工具 request_replan
                                  sessionRef      ← 开始/sessionRef
                                  assessmentText  ← 大模型A/raw_output
                                  │
                                  └─► 大模型B（总结 + 是否调整计划）
                                        query         ← 开始/query
                                        gradeResult   ← 工具grade/content[0].text
                                        masteryResult ← 工具mastery/content[0].text
                                        planChange    ← 工具replan/content[0].text
                                        │
                                        └─► 结束 result ← 大模型B/raw_output
```

> ⚠️ **下游节点只拿得到直接上游的数据**。大模型 B 接在 `request_replan` 后面，
> 默认看不到更早的判分结果——必须像上表那样把三个工具的输出**都显式接进来**，
> 否则它只能说"本次未返回得分"。

**大模型A 提示词**

```text
你会收到 grade_exercise 的结果 JSON（score、perKnowledgeAccuracy、errorTypes）。

输出两段内容，必须是合法 JSON：
{"updates":[{"knowledgePointId":"...","assessmentScore":66.67}],
 "assessment":{"masteryScore":<旧掌握度>,"assessmentScore":<本次得分>,"incompleteTasks":0,"repeatedError":true,"knowledgePointId":"..."}}

规则：分数只能取 JSON 里的数值，禁止自算；`assessmentScore` 用 score 原值；`repeatedError` 在 score<80 时为 true。
```

**大模型B 提示词**

```text
你会收到三段 JSON：
1. gradeResult：判分结果（score、perKnowledgeAccuracy、errorTypes）
2. masteryResult：画像更新结果（updates、assessment、profileVersion）
3. planChange：重排结果（needReplan、changed、planDiff）

用中文总结，150 字以内：
- 这次得了多少分（取 score 原值）
- 哪个知识点最弱（取 perKnowledgeAccuracy 里正确率最低的；只有一条就直接说它）
- 计划是否需要调整（needReplan）、调整了什么（planDiff.changedTasks）

规则：数值只能引用这三段 JSON；缺失就直说"本次未返回该项"，不要推测。
```

**测试用例**

| # | 输入 | 期望 |
|---|---|---|
| A1 | answers=`[{"exerciseId":"ex-demo-1","answer":"B"}]` | score=100；mastery 提升；`needReplan=false` |
| A2 | answer 改成「A」（错） | score=0；mastery 下降；`repeatedError=true` |
| A3 | exerciseId 不存在 | `isError=true`（服务端拒绝判分，返回 NOT_FOUND） |
| A4 | answers 传非法 JSON 文本 | `isError=true`，`VALIDATION_ERROR` |
| A5 | 重复提交同一 answers | 掌握度只更新一次（幂等/版本保护） |

## 断言顺序（建议）

```text
1. 工具能不能通：isError=false
2. 大模型能不能读到数据：tool_output 不为空
3. 输出结构对不对：是 JSON、字段齐全
4. 业务值对不对：总时长、分数、知识点 ID
5. 异常分支：伪造 sessionRef → 必须报错而不是继续
```
