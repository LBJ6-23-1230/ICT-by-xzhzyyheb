# S4 平台资产搭建步骤（控制台施工单）

> 目标：把「一个空壳智能体」变成「能查数据、能引用资料、能出题判分的多智能体应用」。
> 每个阶段都有验收点，**上一个阶段没通过，不要进下一个**。

| 阶段 | 产出 | 预计 |
|---|---|---|
| 1 | 单智能体可用（提示词 + MCP + 知识库） | 40 分钟 |
| 2 | 4 条能力工作流（诊断/规划/练习/评估） | 2 小时 |
| 3 | 多智能体控制器（意图路由） | 1 小时 |
| 4 | 发布 + 调用链证据 | 30 分钟 |

---

## 阶段 1：把单智能体做成"能用"

对象：`zhixue-agent-v2`（如果它已被弄乱，新建一个 `zhixue-agent`，别再复制旧的）

### 1.1 提示词（整段替换）

```text
你是「知学 Mate」的学习规划助手，服务对象是大学生。

你的职责：把用户模糊的学习诉求，变成有依据、可执行的安排。

工作规则：
1. 用户提到学习目标、时间安排、薄弱点、练习或判分时，必须先调用工具拿真实数据，再回答。禁止凭对话内容猜测课程、掌握度或计划。
2. 所有工具都需要 sessionRef 参数。能从上下文拿到就直接用；拿不到就如实说「当前会话缺少身份引用，无法读取你的学习数据」，不要编造。
3. 只依据工具返回的数据下结论。没有证据时明确说「证据不足，建议先做一次短测」，不要给薄弱点排名。
4. 分数只能来自 grade_exercise 的返回值，不得自行计算或估计。
5. 时间预算必须遵守：用户说多少分钟，就只排多少分钟。排不下的任务要显式说明「延期」，不要偷偷删掉。
6. 引用资料时给出文件名与章节（来自 search_learning_materials 的 fileName / headingPath）。
7. 用中文回答，先结论后理由，控制在 200 字以内；需要展示计划时用列表。
```

### 1.2 入参变量

技能下方 **记忆 → 入参变量 → +**：

| 变量名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `sessionRef` | string | 空 | 网关传入的一次性会话引用，用于工具鉴权 |

### 1.3 知识库（先传 2 份就够）

1. 左侧 **知识库 → 创建**：名称 `课程资料库`，其余默认
2. 上传 2 份讲义（**docx / pdf / pptx / xlsx / csv**，平台不支持 md/txt）
3. 等解析完成，确认切片数和知识点被识别出来
4. 回到智能体 → 技能 → **知识库 → +** → 关联这个库

> 基础版每个应用只能关联 **1 个**知识库，所以语料要一次选对。

### 1.4 对话体验

| 开关 | 设置 | 原因 |
|---|---|---|
| 追问 | 开 | 缺参数时它会主动问 |
| **引用和归属** | **开** | 知识库回答要能显示来源 |
| 内容审核配置 | **联调阶段先关** | 它会把正常回复拦成空 |

### 1.5 验收（三条）

| 测试问句 | 期望 |
|---|---|
| 「你好」 | 正常回复，不卡在"正在识别" |
| 「我今晚只有 60 分钟，怎么安排」 | 调 `get_learning_context` 或 `fit_plan_to_budget`；可能返回 `UNAUTHORIZED`（没有真 sessionRef，**正常**） |
| 「二叉树后序遍历是什么」 | 回答并显示引用来源（文件名 + 章节） |

> 第三问如果答不上来，说明知识库没关联或语料没解析成功。

## 阶段 2：4 条能力工作流

入口：左侧 **智能体管理 → 工作流 → 创建**。

每条的骨架一致：

```text
开始（入参：query, sessionRef）
  → 知识检索（可选）
  → 大模型（角色提示词 + 结构化输出）
  → 工具节点（MCP，按需）
  → 条件分支（成功 / 证据不足 / 工具失败）
  → 结束（输出结构化 JSON）
```

### 2.1 学情诊断 `wf-diagnosis`

**入参**：`query`、`sessionRef`

| 节点 | 配置 |
|---|---|
| 工具 | `get_learning_evidence`（参数 `sessionRef`） |
| 条件（可选） | **默认不做结构化分支**：MCP 节点输出是 JSON 文本，条件节点取不到 `data.hasEvidence`。要分支就加代码节点解析，或把判断交给模型 |
| 大模型提示词 | 见下 |
| 输出 | `{weakPoints[], confidence, evidenceIds[], needsShortTest}` |

> ⚠️ **踩过的坑**：工作流的条件分支只能比较简单变量，**不能索引工具返回 JSON 里的字段**。
> 所以「证据不足 → 建议短测」这个分支，正确做法是让**模型输出 `needsShortTest` 字段**，
> 由控制器/前端据此分支；只有确实需要确定性分支时，才加代码节点解析信封。

```text
你是学情诊断专家。你会收到工具返回的 JSON 文本，先看 data.hasEvidence 字段。

规则：
- hasEvidence 为 false：只输出 {"needsShortTest": true, "message": "证据不足，建议先做 3 题短测"}，不要列薄弱点。
- hasEvidence 为 true：按证据列出最多 3 个薄弱点，输出 {"needsShortTest": false, "weakPoints": [...], "evidenceIds": [...]}。
- 只能使用 JSON 里的数据，禁止补充外部知识；每个薄弱点必须带 evidenceIds。
- 按薄弱程度排序。
```

### 2.2 学习规划 `wf-planner`

**入参**：`query`、`sessionRef`、`availableMinutes`（数字，可空）

| 节点 | 配置 |
|---|---|
| 工具 1 | `get_learning_context` |
| 工具 2 | `calculate_learning_priority`（候选知识点数组来自上一步） |
| 工具 3 | `fit_plan_to_budget`（`availableMinutes`） |
| 工具 4 | `save_learning_plan`（`expectedVersion` 取上下文里的 plan.version，首次 0；`idempotencyKey` 用会话 ID） |
| 输出 | `{plan, budgetSummary, deferred[], reasons[]}` |

```text
你是学习规划专家。把薄弱点、DDL、可用时间变成一份可执行的计划。

规则：
- 总时长不得超过 availableMinutes。排不下的任务必须放入 deferred 并写明原因。
- 每个任务给出：知识点、时长（分钟）、完成标准、优先级理由。
- 计划版本冲突（工具返回 CONFLICT）时，重新读取上下文再生成，不要重试同一份。
- 不要把"复习"写成笼统任务，要落到具体知识点。
输出 JSON：plan（tasks 数组）、budgetSummary、deferred、reasons。
```

### 2.3 练习辅导 `wf-exercise`

**入参**：`query`、`sessionRef`、`knowledgePointId`

| 节点 | 配置 |
|---|---|
| 工具 1 | `search_learning_materials`（query=知识点名） |
| 工具 2 | `create_grounded_exercise`（点、题量 3） |
| 条件 | 返回 `INSUFFICIENT_MATERIALS` → 提示补资料，**不出通用题** |
| 输出 | `{exercises[], sources[]}` |

```text
你是出题助手。只基于用户已上传的资料出题。

规则：
- 题目必须能追溯到检索到的片段，输出里带上 sources（fileName、headingPath、chunkId）。
- 资料不足时返回错误说明，不要用通用题库冒充"依据资料"。
- 题干清晰、选项四个、只有一个正确答案，不要泄露答案。
输出 JSON：exercises（stem、options、difficulty、knowledgePointId）、sources。
```

### 2.4 学习评估 `wf-assessment`

**入参**：`query`、`sessionRef`、`answers`

| 节点 | 配置 |
|---|---|
| 工具 1 | `grade_exercise`（**只传 answers，不要传答案键**） |
| 工具 2 | `update_mastery`（`assessmentScore` 来自上一步） |
| 工具 3 | `request_replan`（评估结果） |
| 输出 | `{score, perPoint[], needReplan, reasons[]}` |

```text
你是评估助手。分数只能来自 grade_exercise 的返回值。

规则：
- 禁止自行计算分数、禁止估计掌握度。
- 逐知识点说明正确率与错因，错因要具体到"概念混淆/步骤遗漏/计算错误"。
- 若 needReplan 为 true，说明要调整计划，并给出调整理由。
输出 JSON：score、perPoint（知识点、正确率、新掌握度）、needReplan、reasons。
```

### 2.5 验收

每条工作流单独**试运行**，输入里填：

```json
{"query": "测试", "sessionRef": "sref-demo-0000000000000001", "availableMinutes": 60}
```

| 检查 | 期望 |
|---|---|
| 节点逐个变绿 | 无红色节点 |
| 输出结构 | 含约定字段，不是一段散文 |
| 异常分支 | 把 sessionRef 改错，应返回 `UNAUTHORIZED` 而不是崩溃 |

> `sessionRef` 需要服务器有对应数据，见 `tools/seed_mcp_demo.py`。

## 阶段 3：多智能体控制器

入口：**智能体管理 → 多智能体 → 创建**。

| 配置 | 填什么 |
|---|---|
| 名称 | `zhixue-controller` |
| 子智能体 | 添加 4 条工作流（`wf-diagnosis` / `wf-planner` / `wf-exercise` / `wf-assessment`） |
| 意图识别 | 优先用**意图识别工作流**；没有就用模型配置 |
| 执行动作 | 每个子流程设 **继续 / 终止 / 等待输入** |
| 最大对话历史轮次 | 10 |
| 最大跳转次数 | **6~8**（防死循环） |

意图路由规则（写进控制器提示词）：

```text
你是「知学 Mate」的总控。根据用户意图把任务交给对应工作流：
- 问"哪里薄弱/为什么错" → wf-diagnosis
- 问"怎么安排/时间不够/先学什么" → wf-planner
- 问"出几道题练练/要题目" → wf-exercise
- 提交答案/问"我做得怎么样/要不要改计划" → wf-assessment
- 闲聊或与学习无关 → 直接应答，不要转交
- 信息不足（缺时间、缺目标、缺知识点） → 执行"等待输入"，先追问

禁止在一次对话里把所有工作流都跑一遍。
```

### 验收

| 测试 | 期望 |
|---|---|
| 「我今晚只有 60 分钟」 | 只进 `wf-planner`，不连带诊断和练习 |
| 「帮我看看我哪里薄弱」 | 进 `wf-diagnosis`；无证据时建议短测 |
| 「随便聊聊」 | 直接应答，不进任何工作流 |
| 「帮我安排复习」（缺时间） | 追问可用时间（等待输入） |

## 阶段 4：发布与证据

1. 提交版本 → 命名 `v1.0-s4` → 勾选部署至实例 → **模型 API Key 必须填 MaaS Key**
2. 入站认证：API Key；调用链：**开启**
3. 部署后拿：运行时名称、访问域名、API Key
4. 更新本机 `.env`（`AGENTARTS_RUNTIME_NAME`、`AGENTARTS_API_KEY`）
5. 跑 `python tools/check_agentarts_runtime.py --host ... --runtime ... --key ...`
6. 进 **运营运维 → 观测 → 调用链管理**，按会话 ID 找到这次调用，**截图 + 导出字段表**，存 `ICT/evidence/s4-trace/`

> 基础版 Trace 只留 15 天，当场归档。

## 已知坑（都是踩过的）

| 坑 | 表现 | 处理 |
|---|---|---|
| 提示词是空壳（只有 "1"） | 预览卡在"正在识别您要做什么" | 粘 1.1 的完整提示词 |
| 模型鉴权没配 | 流里返回 `error 100025`，HTTP 却是 200 | 部署时填 MaaS API Key |
| 知识库语料是 md/txt | 上传成功但检索不到 | 转成 docx/pdf 再传 |
| 基础版知识库限制 | 想关联第二个库时选不到 | 每应用只能 1 个，合并语料 |
| MCP 工具没绑 sessionRef | 工具返回 `UNAUTHORIZED` | 入参变量 `sessionRef` + 网关注入 |
| 一次对话跑完所有工作流 | 响应慢、结论互相矛盾 | 控制器加"禁止全跑"约束 |
