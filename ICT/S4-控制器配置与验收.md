# S4 多智能体控制器：配置与验收

> 四条能力工作流已各自跑通。控制器要解决的是**路由**：一句话该交给谁、什么时候不该转交。
> 没有控制器，"四个工作流"不构成"多 Agent 协作"。

## 1. 目标结构

```text
用户一句话
   │
   ▼
zhixue-controller（多智能体 / 控制器）
   ├─ wf-diagnosis   学情诊断
   ├─ wf-planner     学习规划
   ├─ wf-exercise    练习辅导
   └─ wf-assessment  学习评估
   │
   └─ 直接应答（闲聊 / 越界问题，不转交）
```

## 2. 创建

1. 智能体管理 → **多智能体** → 创建
2. 名称：`zhixue-controller`
3. 模型：与子工作流一致（`DeepSeek-V4.1-Flash`）
4. 添加子智能体：4 条工作流全部加入
5. 全局配置 → 输入参数：`query`(String)、`sessionRef`(String)

## 3. 子工作流入参映射

| 子工作流 | 入参 | 来源 |
|---|---|---|
| wf-diagnosis | `query`、`sessionRef` | 控制器入参 |
| wf-planner | `query`、`sessionRef`、`availableMinutes`(Integer) | 控制器入参；时间从用户话里抽，抽不到走"等待输入" |
| wf-exercise | `query`、`sessionRef`、`knowledgePointId`(String) | 知识点优先取诊断结果，其次问用户 |
| wf-assessment | `query`、`sessionRef`、`answers`(Array) | 用户提交的作答 |

> 抽不到参数时**不要瞎填**：执行"等待输入"，让控制器先追问一句。

## 4. 控制器提示词

```text
你是「知学 Mate」的总控，服务对象是大学生。你不亲自分析学情，只负责分派。

路由规则：
1. 问"哪里薄弱 / 为什么错 / 我的短板" → wf-diagnosis
2. 问"怎么安排 / 时间不够 / 先学什么 / 帮我排计划" → wf-planner
3. 问"出几道题 / 想练练 / 给我题目" → wf-exercise
4. 提交答案（含 A/B/C/D）或问"我做得怎么样 / 要不要改计划" → wf-assessment
5. 闲聊、问身份、与学习无关 → 直接应答，禁止转交
6. 信息不足（缺时间、缺知识点、缺作答）→ 执行"等待输入"，先追问一句再转交

硬性约束：
- 一次只转交一条工作流，禁止同时调用多条。
- 不要在转交前自己编造学习数据、计划或分数。
- 转交时把用户原话和已有参数一起传下去；用户没说的参数不要猜。
- 子工作流返回后，用它的结论回答，不要二次加工数字。
```

## 5. 高级配置

| 项 | 值 | 原因 |
|---|---|---|
| 最大对话历史轮次 | 10 | 默认即可 |
| 最大跳转次数 | **6**（不要用默认 9） | 防止"诊断→规划→再诊断"打转烧额度 |
| 启动/默认工作流 | 不设 | 让模型按意图判断 |
| 结束条件 | 子工作流返回即结束 | 避免控制器再总结一遍（会重复内容） |
| 等待输入 | 允许 | 缺参数时追问，这是澄清闭环 |

## 6. 验收用例

| # | 输入 | 期望 | 证明什么 |
|---|---|---|---|
| C1 | 我今晚只有 60 分钟 | **只**进 `wf-planner` | 路由准确，不连带跑 |
| C2 | 帮我看看我哪里薄弱 | 进 `wf-diagnosis` | 意图识别 |
| C3 | 随便聊聊 / 你是谁 | **直接应答**，不进任何工作流 | 不滥用工具 |
| C4 | 帮我安排复习（没说时间） | 追问"每天能学多久"（等待输入） | 澄清能力 |
| C5 | 我选了 B（无上下文） | 追问"哪道题 / 哪套题" | 不凭空判分 |

> C3 和 C4 最容易被忽略，但评委最爱问："简单问题会不会也跑一遍全流程？"
> 这两条就是答案。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 一句话触发了多条工作流 | 提示词没写"一次只转交一条" | 加硬性约束第 1 条 |
| 闲聊也去调工具 | 没有"直接应答"分支 | 加规则 5 |
| 子工作流收到空 `sessionRef` | 控制器没把入参透传 | 在每个子工作流映射里显式引用控制器入参 |
| 回答重复两遍 | 控制器和子工作流都做了总结 | 结束条件设为"子工作流返回即结束" |
| 反复来回跳转 | 最大跳转次数太大 | 调到 6，并让子工作流"返回即结束" |

## 8. 建完之后

```text

2. 更新本机 .env：
     AGENTARTS_RUNTIME_NAME / AGENTARTS_API_KEY / AGENTARTS_ENDPOINT
3. python tools/check_agentarts_runtime.py --host ... --runtime ... --key ...
4. 归档：ICT/evidence/s4-controller.md（C1–C5 五条截图）
5. 进入 S5：Web Demo 调控制器运行时
```

## 9. 一句话判断控制器是否合格

> 能用**一句话**说出"为什么这句话分给了这条工作流"，且**闲聊不会被分派**——就合格。
>
> 如果只能演示"每种意图各说一句"，但答不出"为什么不是另一条"，说明路由靠碰运气。
