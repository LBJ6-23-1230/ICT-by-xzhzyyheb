# S5 图片错题诊断

> 原项目有"拍照诊断"，迁到 AgentArts 后一度丢了。这一节把它接回来，
> 并且明确一件事：**识别归识别，诊断归诊断**。

## 一、为什么放在网关，不做成 MCP 工具

| 方案 | 问题 |
|---|---|
| 做成 MCP 工具（base64 入参） | 图片动辄几 MB，base64 塞进模型上下文会直接撑爆；且 MCP 每传一次都算 token |
| **放在网关** | 图片不进模型上下文；识别失败与诊断失败在日志里分得开 |

职责边界：

```text
用户 📷 拍照
   ↓
网关 POST /api/v2/agent/vision      ← 只做识别：题干 / 选项 / 疑似知识点 / 疑似错因
   ↓ 返回 suggestedQuery
前端填入输入框（用户确认）
   ↓
POST /api/v2/agent/chat             ← 走云端 wf-diagnosis，基于真实证据给结论
```

**关键设计**：识别不直接触发诊断。用户先看到"我识别到了什么"，确认无误再发。
否则识别错了，后面的诊断会一本正经地分析一道不存在的题。

## 二、接口

```http
POST /api/v2/agent/vision
Content-Type: application/json

{"imageBase64": "<base64，可带 data: 前缀>"}
```

成功（200）：

```json
{
  "readable": true,
  "stem": "已知二叉树后序遍历为 D A B E C，则其前序遍历是？",
  "options": ["A. A B D E C", "B. ..."],
  "questionType": "single_choice",
  "knowledgePointGuess": "二叉树遍历",
  "errorTypeGuess": "",
  "handwriting": true,
  "confidence": 0.86,
  "suggestedQuery": "已知二叉树后序遍历为…（选项：A… / B…）",
  "fallback": false
}
```

识别失败（400）：

```json
{"errorCode": "VISION_BAD_OUTPUT", "message": "识图结果无法解析，请重拍或手动输入题目", "fallback": false}
```

错误码：

| 码 | 含义 | 前端处理 |
|---|---|---|
| `VALIDATION_ERROR` | 缺图片 / base64 非法 | 提示重选 |
| `PAYLOAD_TOO_LARGE` | 超过 5MB（压缩后仍超） | 提示压缩或重拍 |
| `VISION_UNAVAILABLE` | 视觉模型调不通（Key/网络） | 提示"改用文字输入" |
| `VISION_BAD_OUTPUT` | 模型输出无法解析 | 提示重拍 |

## 三、前端行为

| 场景 | 表现 |
|---|---|
| 识别成功 | 对话区显示识别到的题干与选项；输入框预填"我拍了这道错题：…，帮我看看错在哪"；证据栏显示知识点与把握 |
| `readable=false` | 明说"没识别出题目 + 原因"，并提示可直接打字 —— **不猜知识点** |
| 把握 < 50% | 证据栏显示真实百分比，用户自行判断是否重拍 |
| 图片过大 | 前端先压到长边 1600px 再上传，正常手机照片不会触发上限 |

## 四、验收用例

| # | 操作 | 期望 | 证明 |
|---|---|---|---|
| V1 | 拍一张清晰的选择题 | 识别出题干与 4 个选项，把握 > 0.6 | 基本可用 |
| V2 | 确认后发送，走诊断 | 时间线出现 `wf-diagnosis`，结论引用识别出的知识点 | 识别 → 诊断接得上 |
| V3 | 拍一张模糊照片 / 拍桌面 | `readable=false`，给出原因，不编知识点 | **失败不造假** |
| V4 | 拍一张非题目（如教材目录） | 同上，或识别出"这不是一道题" | 边界正确 |

V3/V4 是重点：**识别失败时能承认失败**，比识别成功更能说明系统可信。

### 需要的环境变量（网关）

```bash
grep -E 'DASHSCOPE_API_KEY|LLM_VL_MODEL|LLM_BASE_URL' /opt/zhixue/gateway.env
```

| 变量 | 作用 | 缺了会怎样 |
|---|---|---|
| `DASHSCOPE_API_KEY` | 视觉模型鉴权 | `VISION_UNAVAILABLE` |
| `LLM_VL_MODEL` | 视觉模型名（默认 `qwen-vl-max`） | 用默认值即可 |

## 六、已知限制

| 项 | 说明 |
|---|---|
| 图片不进 AgentArts Trace | 识别在网关完成，平台侧只看到"诊断了这段文本" |
| 不做自动判分 | 识别出的选项不自动判对错——判分只认服务器里的 `answerKey`，避免"看图猜答案" |
| 手写公式识别有限 | 复杂公式（矩阵、积分）容易错，V3 会如实提示 |
| 单图 | 一次只识别一张；多页题目需要分次 |

## 七、答辩话术

> "拍照这一环我们没有交给平台模型硬扛——图片在网关先转成结构化文本，
> 用户能看见识别结果并确认，再进诊断。这样识别错和诊断错不会混在一起。
> 拍不清楚的时候它会直接说识别不出来，而不是编一个知识点。"
