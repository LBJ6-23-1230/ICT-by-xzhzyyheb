# S5 错题诊断与学情更新

> 目标：把"拍一张错题"变成**真的改变学情**的动作——错题入库、掌握度下降、诊断能看见它。
> 只讲题不动学情，那只是个聊天窗口；动了学情，才算"学习伴侣"。

## 一、闭环设计

```text
📷 拍题 → 网关识别（只识别，不判分）
             ↓ suggestedQuery（用户确认）
       控制器路由：包含具体题目 + "我错了 / 这题不会" → wf-tutor
             ↓
   wf-tutor：查资料 → 查证据 → 讲解 →（确认做错）→ 记错题
             ↓ record_wrong_question
       错题本 + 掌握度下调（复用判分同一套规则）
             ↓
   下次 wf-diagnosis 的薄弱点里就能看到它
```

## 二、新工具 `record_wrong_question`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sessionRef` | string | ✅ | 换 userId，模型传 userId 会被拒 |
| `knowledgePointId` | string | ✅ | 这道题考查的知识点 |
| `stem` | string | ✅ | 题干原文（识别结果或用户输入） |
| `knowledgePointName` | string | | 中文名，缺省用 ID |
| `reason` | string | | 错因/解析，写进错题本 |
| `sourceType` | string | | `photo` / `manual` / `bank`，默认 `photo` |
| `exerciseId` | string | | 省略时按题干+知识点哈希生成，同题重复录入只增计数 |
| `assessmentScore` | integer | | 默认 `0`（做错），可传 0~100 |

返回：

```json
{"wrongBookId": "demo-user:wrong-3f9a1c7b2e", "exerciseId": "wrong-3f9a1c7b2e",
 "knowledgePointId": "binary-tree-traversal", "wrongCount": 1,
 "assessmentScore": 0, "oldScore": 58, "newScore": 54, "profileVersion": 5}
```

### 三个设计决定

1. **一个工具同时落库 + 减分**：拆成两个工具意味着工作流多一个节点、多一次结构化传参，
   我们在 `fit_plan_to_budget` 上已经为此付过代价。参数全用字符串，工作流好接。
2. **减分复用判分规则**（`assessment.update_mastery`）：错题和判分不能有两套口径，
   否则同一份数据在不同入口得到不同掌握度。
3. **同题去重**：按题干哈希生成 `exerciseId`，重复录入只累加 `wrongCount`，
   不会把错题本刷成几十条一样的东西。

### 已验证（S3 自检新增 5 项）

```text
[OK] 错题录入成功
[OK] 错题让掌握度下降（58 → 54）
[OK] 错题按内容生成稳定题号
[OK] 错题出现在证据里（wrongBookCount ≥ 1）
[OK] 健康检查列出写操作（含 record_wrong_question）
```

## 三、新建 `wf-tutor`（错题讲解 + 落库）

### 节点

```text
开始(query, sessionRef)
  → 工具 search_learning_materials(sessionRef, query)
  → 工具 get_learning_evidence(sessionRef, knowledgePointId)
  → 大模型A（讲解 + 判断是否确认做错，输出 JSON）
  → 判断（confirmedWrong == "true"）
        ├─ 是 → 工具 record_wrong_question(sessionRef, knowledgePointId, stem, reason)
        │        → 大模型B（总结：讲解 + 掌握度 58→54）
        └─ 否 → 大模型B（只讲解，不落库）
  → 结束
```

> `knowledgePointId` 从哪来：识别阶段已把它写进 query，或让大模型A从 query + 资料里判断。
> 生产上更稳的是让前端把 `knowledgePointGuess` 一起传进 `query`（现在的 `suggestedQuery` 已带题干与选项）。

### 大模型A 提示词

```text
你是错题讲解老师。你会收到两段数据：讲义片段（可能为空）、该知识点的掌握度与错题数（可能为空）。

第一步：判断用户是否明确"这道题做错了/不会做"（例如"我错了""这题不会""记一下""帮我记到错题本"）。
第二步：讲解这道题。

只输出 JSON：
{"confirmedWrong": true 或 false,
 "knowledgePointId": "与证据数据一致的知识点 ID，判断不出就留空",
 "stem": "题干原文，取自用户这句话",
 "reason": "错因（一句话）",
 "explanation": "给用户看的讲解，120 字以内"}

规则：
- 用户只是问"这题怎么做"，不要认定为做错，confirmedWrong 用 false。
- knowledgePointId 只能在证据或题目内容里有依据时才填，禁止猜。
- 讲解优先引用讲义片段；引用时写"依据：<文件名> · <章节>"，没有依据就不要编来源。
- 不要输出 JSON 之外的内容。
```

### 大模型B 提示词

```text
你会收到讲解结果。用中文回答用户，150 字以内：
- 先讲清正确思路（3~5 句）
- 若有资料依据，写"依据：<文件名> · <章节>"
- 若本次已记入错题本，最后一句说明"已记入错题本，该知识点掌握度 58 → 54"

数值只能引用 JSON 里的值；缺失就说"暂无记录"，不要推测。
```

### 控制器加一条路由

```text
- 用户贴了一道具体题目，或说"这题我错了/不会"，或发了拍照识别结果 → wf-tutor
- 问"我哪里薄弱/整体情况" → wf-diagnosis
- 问"怎么安排/时间不够" → wf-planner
- 问"出几道题" → wf-exercise
- 提交答案问"我做得怎么样" → wf-assessment
```

## 四、验收

| # | 操作 | 期望 | 证明 |
|---|---|---|---|
| W1 | 拍一道选择题 → 识别 → 发"我错了，帮我看看" | 讲解正确思路；时间线出现 `wf-tutor` 与 `record_wrong_question` | 讲解 + 落库 |
| W2 | 同一张图再发一次 | `wrongCount` 变 2，题号不变 | 去重生效 |
| W3 | 发"帮我看看我哪里薄弱" | 薄弱点里出现刚才那个知识点，掌握度已下降 | **学情真的变了** |
| W4 | 只问"这题怎么做"（不说做错） | 有讲解、**不落库**、掌握度不变 | 不误伤学情 |

W3 是核心：**从错题到学情，闭环可验证**。W4 是防误伤——不确认做错就不动掌握度。

## 五、答辩话术

> "拍照不是只能看个答案。确认做错之后，这道题会进错题本，同时按判分同一套规则下调
> 这个知识点的掌握度。所以下一次诊断，薄弱点里就会出现它——错了会留下痕迹，
> 学习建议才会跟着变。只问'这题怎么做'不会动掌握度，避免把没做错的题也算进去。"
