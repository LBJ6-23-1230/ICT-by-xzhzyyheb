# 赛题对齐与改动清单（依据官方原文）

> 依据：赛题 2 任务要求 + 初赛评审规则（创新性 60%、应用价值 40%）。
> 本文取代此前《项目定位与目标形态》中关于评分权重的推测。

## 一、官方要求的逐条对照

### 任务要求

| 官方要求 | 我们现状 | 判定 |
|---|---|---|
| 基于 AgentArts 完成智能体**构建、编排、部署** | 控制器 + 5 条工作流 + 运行时已部署 | ✅ |
| 通过**可视化 Demo 页面**展示核心功能与交互 | `/demo` 三栏页面 | ✅ |
| 体现 **智能体设计** 的使用价值 | 控制器 + 分工提示词 | ⚠️ 有，但"为什么这样分工"没呈现给评委 |
| 体现 **工具编排** 的使用价值 | MCP 12 工具 | ✅ 有，但界面只显示工具名 |
| 体现 **知识接入** 的使用价值 | 上传 → 切片 → 检索 → 出题带来源 | ⚠️ 引用只出现在回答文字里 |
| 体现 **多 Agent 协作** 的使用价值 | 控制器路由到 5 条工作流 | ⚠️ 时间线只显示"交给谁"，没显示"为什么不是别人" |
| 体现 **效果评估** 的使用价值 | **无** | ❌ 缺 |
| 场景识别 → 架构设计 → 技能编排 → 调试优化 → 部署上线的**完整闭环** | 过程真实发生过（大量踩坑与修复） | ⚠️ 有素材，没整理成叙事 |

### 评审规则

| 维度 | 权重 | 考什么 | 我们现在的回答 |
|---|---|---|---|
| **创新性** | **60%** | 场景创新 / 差异化优势 / 智能体设计思路或交互方式创新 | ⚠️ 只有"老实"没有"新" |
| **应用价值** | 40% | 真实需求、商用落地潜力、可复制规模化、架构合理可行 | ✅ 基本具备，但没讲成"可复制" |

**结论：我们现在的作品"技术上成立、叙事上平庸"。**
60% 的创新性目前只能靠"模型不许编数字"这一条撑，而它偏工程严谨，不是场景/交互创新。

## 二、必须补的创新点（可落地、能一眼看懂）

以下是三个候选，建议**全做但分级**：A 是主叙事，B 是视觉证据，C 是加分细节。

### A（主叙事）"可核验的学习闭环"

一句话：**界面上每个数字都能点开，看到它是怎么来的。**

```text
掌握度 54  [🧮 计算]  ← 点击展开
   ├─ 由 4 次判分 + 2 道错题推导（列表 + 时间）
   ├─ 规则：score<60 → -4（规则号 R2）
   └─ 最近一次：2026-11-10 18:52，错题 wrong-3f9a1c7b2e

回答"建议先练二叉树遍历"  [📚 资料]  ← 点击展开
   ├─ 依据：二叉树讲义.pdf · 第3章 3.2
   ├─ 片段哈希：0f8c5b5d…（可核对原文）
   └─ 若资料里没有：显示"无资料依据"
```

为什么算创新：市面上的学习 App 都在"给建议"，没人把**建议的依据链**摆出来。
这直接对应"Agent 架构设计合理、可行"，也把"模型不许编数字"从口号变成可见界面。

**工作量**：前端 3 小时（后端数据都已有：`masteryUpdates`、`sources`、`wrong_book`）。

### B（视觉证据）"多 Agent 分工可视化"

时间线从"交给 wf-planner"升级为：

```text
🧭 控制器决策
   意图：时间安排（置信 0.86）
   → 选择 wf-planner
   → 排除 wf-diagnosis（问的是"怎么排"，不是"哪里弱"）
   → 排除 wf-exercise（没要求出题）

📋 wf-planner 执行中
   🛠 get_learning_context   412ms  ✅
   🛠 fit_plan_to_budget     689ms  ✅ 45 分钟排入 / 70 延期
```

为什么算创新：**"为什么不是别的 Agent"** 几乎没人展示，而这正是"多 Agent 协作"的证明。

**工作量**：网关 1 小时（把 `subagent_started` + 工具事件拼成决策摘要）；
"排除项"需要控制器输出理由——若平台不给，就由网关按工作流名 + 用户原话生成一句依据。

### C（加分细节）"计算值 / 生成值"标签

每个数字旁标 🧮 或 🧠；每个引用标 📚。
一眼能看出"哪些是算的、哪些是模型说的"——这是**交互方式的创新**，成本极低（前端 1 小时）。

## 五、三分钟视频脚本（按 60/40 组织）

| 时间 | 内容 | 对应评分 |
|---|---|---|
| 0:00–0:25 | 痛点：错题本越攒越厚，但没人告诉你"下一步练什么" | 应用价值 |
| 0:25–1:00 | 拍一道错题 → 识别 → 讲解 → **掌握度 58→54**（数字可点开看依据） | 创新性 A |
| 1:00–1:40 | 问"我哪里薄弱" → 时间线显示控制器**选谁、排除谁** | 创新性 B |
| 1:40–2:20 | 问"60 分钟怎么安排" → 45 排入 / 70 延期，延期带原因 | 应用价值（可执行） |
| 2:20–2:45 | 上传新讲义 → 立刻出题，题目带"依据：文件·章节" | 知识接入 |
| 2:45–3:00 | 一句设计原则：**模型只判断，不算数** | 创新性总结 |

## 六、一句话调整

> 之前我们在做"功能完整的 Agent 应用"；
> 现在要做成**"一个把决策依据摆到台面上的 Agent 应用"**——这才是 60% 创新性要的东西。

功能不需要再加，需要把**已有能力的依据链可视化**。这也意味着：

* 不再新增大功能（登录、多端、社交都停）
* 把 3 小时投在"数字可点开"，比投在"再加一个工作流"回报高得多
