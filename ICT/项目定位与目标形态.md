# 项目定位与目标形态（ICT 赛题 2）

> 目的：在继续堆功能之前，先回答"这到底要交一个什么东西"。
> 说明：本文对评分维度的判断来自赛事通识与往年创新赛惯例，**不是官方原文**；
> 官方评分表拿到后应回来校准一次。

## 一、先把老项目说清楚

**知学 Mate**：HarmonyOS App + Flask 后端 + PostgreSQL。

```text
App（19 个页面）
   ↓ HTTP
Flask 后端
   ├─ 意图识别：chat_llm.detect_intent()  → if/elif 分发到 9 个内部工具
   ├─ 业务：知识库/练习/判分/计划/错题/画像/搭子/专注/推送
   └─ 模型：全部在自建后端调 qwen（文本 + 视觉）
```

它的强项是**功能完整**：能上传讲义、能出题、能判分、能排计划、能拍照识别。
它的本质是**一个单体应用，里面塞了一个会调工具的模型**。

## 二、赛题 2 要的其实不是"应用"，是"Agent 作品"

赛题名是"基于 AgentArts 的 Agent 设计和应用"。三个词分别对应三件事：

| 词 | 对应什么 | 评审会看什么 |
|---|---|---|
| **基于 AgentArts** | 编排必须在平台上 | 智能体/工作流/MCP/知识库/记忆/评测是不是真在用，还是只调了个 API |
| **Agent 设计** | 分工与边界 | 为什么是这几个 Agent、各自职责、路由依据、失败怎么兜 |
| **应用** | 场景闭环 | 能不能解决一个真实问题，且 Demo 跑得起来 |

推论（需官方评分表校准）：**"功能多"不加分，"Agent 分工合理 + 平台能力用透 + 效果可量化"才加分。**

## 三、目标形态：一句话

> **一个跑在 AgentArts 上的多智能体学习伴侣；自建服务退化成"确定性能力后端"，
> 通过 MCP 提供 12 个工具；AgentArts 负责理解、路由、讲解与编排；Web 页面是唯一演示入口。**

```text
                  ┌──────────────────────────────┐
                  │  AgentArts 控制器（多智能体）   │
                  │  理解 / 路由 / 兜底 / 记忆      │
                  └───────┬──────────────────────┘
        ┌─────────┬───────┼────────┬──────────┐
        ▼         ▼       ▼        ▼          ▼
   诊断工作流  规划工作流 出题工作流 评估工作流 讲解工作流
        └─────────┴───────┼────────┴──────────┘
                          ▼
                 MCP（12 个工具，公网 HTTPS）
                          ▼
        自建服务：数据 + 确定性计算（判分/预算/掌握度/重排）
                          ▼
              SQLite / （生产）PostgreSQL + OBS
```

## 四、和老项目的五个本质区别

| 维度 | 老项目 | 新项目 | 为什么这个区别重要 |
|---|---|---|---|
| **编排位置** | Python 里 `if/elif` 意图分发 | 平台上的控制器 + 5 条工作流 | 赛题要的是"在 AgentArts 上设计 Agent"，路由逻辑必须在平台可见 |
| **能力形态** | 内部函数调用 | MCP 协议，12 个工具，可被任何 Agent 复用 | MCP 是平台级能力，也是"解耦"的证明 |
| **模型位置** | 全部在自建后端调 | 理解/讲解交给平台模型；**计算留在工具** | 少一层自建 LLM 依赖，同时形成"模型只判断、不算数"的技术主张 |
| **计算与生成的分工** | 混合 | **确定性计算归工具，生成归模型** | 这是最能讲清的技术主张：分数、预算、掌握度不允许模型编 |
| **交付面** | HAP 安装包 | Web 页面（一个链接） | 线上评审只会打开链接，不会装 App |

补充两个"保留但不强调"的：

* HarmonyOS App：作为"多端"素材保留，时间不够就不投入。
* 推送/搭子/专注：老项目的差异化点，但**与 AgentArts 无关**，不进主线叙事。

## 五、必须补齐的四件事（缺一件就掉档）

### 1. 可量化的效果（S6）——目前最大的空白

评委必问"你怎么证明它有用"。现在只有截图，没有数字。最少要有：

| 指标 | 怎么测 | 现状 |
|---|---|---|
| 路由准确率 | 20 条标注意图 → 看是否进对工作流 | 无 |
| 工具调用正确率 | 任务是否调了该调的工具、参数是否对 | 无 |
| 引用命中率 | 回答/题目是否引用了真实切片 | 无（工具层有，未统计） |
| 幻觉率 | 是否编造了不存在的知识点/分数/来源 | 无 |
| 端到端时延 | 一句话到首个 token / 到结束 | 无 |

**这是从"能跑"到"能比"的分界线。**

### 2. Trace 归档（有时效）

平台基础版调用链只留 15 天，答辩在数月后。**必须当期导出**，按版本存 `evidence/trace/<版本>/`。

### 3. 云资源口径统一（有风险）

出题目前调阿里云百炼的 qwen。赛题是"基于华为云"，这一点会被问。
二选一：换成华为云 MaaS 的 OpenAI 兼容端点（改两个环境变量）；或把出题移到平台侧模型。

### 4. 三分钟可复现的演示脚本

现在能演示，但没有"脚本"。需要一条固定路径、固定输入、固定预期输出，
任何人照着都能复现——这也是评审现场唯一能控制的东西。

## 六、应该砍掉什么

| 砍掉/降级 | 理由 |
|---|---|
| 完整登录体系（手机号+验证码+华为登录） | 与 AgentArts 无关；现场还容易卡在登录页 |
| 搭子/专注/推送 | 老项目亮点，但不在赛题叙事里，讲多了反而稀释重点 |
| 继续打磨工作流参数 | 结构性参数（对象/数组）已证明脆弱，改用字符串参数或让模型产出 |
| 多端同步 | 成本高、演示价值低 |

## 七、三分钟演示脚本（建议）

| 时间 | 动作 | 看得见的东西 |
|---|---|---|
| 0:00–0:20 | 打开 Web 页面，指出"云端 AgentArts"徽标 | 真的在调平台 |
| 0:20–0:50 | 问"我哪里薄弱" | 时间线进 `wf-diagnosis`，薄弱点带掌握度与证据条数 |
| 0:50–1:30 | 问"今晚只有 60 分钟怎么安排" | 进 `wf-planner`，任务排满、延期项带原因 |
| 1:30–2:10 | 拍一张错题 | 识别 → 讲解 → **掌握度 58→54**，错题入库 |
| 2:10–2:40 | 再问"我哪里薄弱" | **刚才那个知识点位置变了**（闭环） |
| 2:40–3:00 | 上传一份新讲义，立刻出题 | 引用显示文件名 + 章节 |

这条脚本的设计意图：**前半段证明"分工"，后半段证明"闭环"，最后 20 秒证明"用户能进来"。**

## 八、一句话判断标准

> 如果评委只记住一句话，希望是：
> **"这个团队把'模型不许编数字'做成了工程约束，并且用多智能体把它们组织成了学习闭环。"**

达不到这句话，功能再多也只是"又一个 AI 学习 App"。
